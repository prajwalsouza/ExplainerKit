Choose a module

Start with a scene, connect values to visual properties, then choose how people experience it. You do not need to learn every module before making an explanation.

Renderers support different effects and resource limits. Three.js is optional and supplied explicitly. Importing core does not fetch dependencies. Importers do not interpret arbitrary executable files; unsupported formats fail explicitly.

Compatibility entries

Use the imports in the tables above for new code. Additional public names include explainerkit/model, explainerkit/modeling, explainerkit/shapes, explainerkit/compose, explainerkit/composition, explainerkit/adaptive, explainerkit/rig, explainerkit/rigging, explainerkit/dom, explainerkit/waapi, explainerkit/timeline and explainerkit/media/audio. They expose the same implementations as their corresponding modules rather than separate engines. The generated API inventory lists every export.

Scope and evidence

Reliable seeking requires the same declared inputs, including seed, data, viewport, interaction and ambient time where relevant. Each module documents its supported formats and work limits. The current live-input guide explains the implemented observations and their device limits. A test pass does not establish physical-device, screen-reader or universal renderer behavior. See the release process, type scope and architecture for their separate checks.
