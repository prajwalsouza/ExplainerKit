Error code catalog

When an operation throws, use its error code to identify the kind of input, feature or object-state failure. The table connects that code to recorded messages and the source checks that raise it, so you can narrow the problem before retrying the call.

Treat the code as the programmatic identifier because explanatory messages can vary. Several checks may raise the same code, and the source links show the locations represented by this catalog rather than proving that every occurrence has the same repair. The suggested checks are starting points that should be read with the actual message and module guide.

The list includes KitError, coded RangeError and unsupported-renderer errors found in the runtime source. Codes invented by application callbacks are outside that list. Diagnostic strings and source identifiers are reproduced from the implementation, so their wording remains exact even where it differs from the explanatory style of the guide.
